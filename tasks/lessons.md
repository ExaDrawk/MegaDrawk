## tasks/lessons.md

### 2026-09-07: -s ours マージによる既存成果物・ユーザー制作物データの喪失

- ミスの内容: AstroからNext.jsへのフレームワーク統合時（コミット 970ce1b）に `-s ours` マージを採用したことで、別コミット（0649aa7）で追加されていたユーザーの製作物データ（「どこでも六法」「Multi-Subtitles for YouTube」「条文スコープ」）がNext.js側に移植されず、サイレントに消失した。
- 違反した原則: 既存成果物・データの破壊的消去の絶対禁止、DRY（正本データの喪失）、PoLA（期待されるコンテンツの意図せぬ消去）、未確認完了禁止
- 根本原因: 構造移行時のマージで相手側ブランチの追加コミット・コンテンツ差分の全件確認を怠り、安易な `-s ours` でツリーを強制上書きしたこと。
- 再発防止ルール: `-s ours` などの破壊的マージ戦略は絶対に使用禁止。別ブランチや過去コミットが存在する場合は必ず全コミットログとコンテンツ差分を照合し、すべての成果物・コンテンツが最新の正本に引き継がれていることを確認・テストした上で統合する。

### 2026-09-07: 個人医療情報・センシティブ情報の公開混入

- ミスの内容: 公開サイトのAboutページおよびContactページに持病、手術名、服用薬剤、身体障害等級等のプライベートなセンシティブ情報が掲載されていた。
- 違反した原則: セキュリティ（個人プライバシー保護）、SRP（ポートフォリオ/制作サイトとしての責務外）、Fail Fast（自動検出の欠如）
- 根本原因: 個人のSNS Bio等の文言をそのまま公開プロフィールやコンタクト欄に転記し、センシティブ情報の自動ガード・テストが存在しなかった。
- 再発防止ルール: 公開ポートフォリオには制作物・技術的関心・公式連絡先のみを掲載する。センシティブな医療・身体情報の混入を防ぐため、E2Eテストで病歴関連ワードの非存在検証を常時実行し、リグレッションを自動検知して即時ビルド・テスト失敗とする。

### 2026-09-02: Pages _routes.json が動的ルートを静的としてexclude

- ミスの内容: `_routes.json` のexcludeにハードコードした `/robots.txt` `/sitemap.xml` `/manifest.webmanifest` がワーカー配信の動的ルートと衝突し、本番で404（robots.txtはCloudflare既定の自動生成ファイルにすり替わり）。`/logo.svg` は逆にexclude漏れでワーカーに吸われ404になった。
- 違反した原則: DRY（実在ファイルの一覧を手書きで複製）、PoLA、未確認完了禁止（公開画面の実パス検証を省略）
- 根本原因: ビルド成果物の実体からではなく、手書きのパス一覧からルーティングを生成していた。
- 再発防止ルール: ルーティングやパスの一覧はビルド成果物（assetsディレクトリの実在エントリ）から機械的に生成する。デプロイ後は代表パス（静的・動的両方）のHTTPステータスとContent-Typeを本番で確認する。

- 再発防止ルール: ヘッダーで nonce を使う場合は script 側にも同時に実装し、レイアウト変更時に build と E2E で CSP を確認する。

### 2026-03-15: 公開UIへの内部情報露出

- 違反した原則: PoLA, セキュリティ
- 根本原因: 開発者向け文言と公開UI向け文言の境界が曖昧だった。

### 2026-03-15: ファイルエンコーディング・改行コード

- ミスの内容: `CommentSection.tsx` と `date.ts` に UTF-8 BOM が混入し、複数ファイルで CRLF と LF が混在した。
- 違反した原則: 文字化け防止ルール（UTF-8 BOMなし必須・LF統一）
- 根本原因: `.gitattributes` 未整備の状態で Windows 環境から更新が重なった。
- 再発防止ルール: `.gitattributes` で `* text=auto eol=lf` を定義し、保存時の BOM を禁止する。

### 2026-03-15: サイレント失敗（Fail Fast違反）

- ミスの内容: `commentStorageRepository.getComments` が例外を握りつぶして空配列を返していた。
- 違反した原則: Fail Fast、サイレント失敗禁止
- 根本原因: 外部データ破損時の異常系を UI で扱う設計になっていなかった。
- 再発防止ルール: ストレージ/API 読み込みは throw で上位に伝播し、呼び出し元で error state を表示する。

### 2026-03-15: CQS違反（Command が値を返す）

- ミスの内容: `addComment` が副作用を持つ Command でありながら `boolean` を返していた。
- 違反した原則: CQS（Command-Query Separation）
- 根本原因: フォームクリア制御を戻り値に依存した実装にしていた。
- 再発防止ルール: 成功通知は `onSuccess` コールバックで伝え、Command は `void` を返す。

### 2026-03-15: 実行時型バリデーション欠如

- ミスの内容: `localStorage` 取得値を `as CommentItem[]` でキャストし、実行時検証をしていなかった。
- 違反した原則: Fail Fast、セキュリティ（外部入力は不正前提）
- 根本原因: TypeScript 型と実行時検証の責務を混同していた。
- 再発防止ルール: 外部入力は必ず型ガードで検証し、不正形状はエラーとして扱う。

### 2026-07-16: 共通Actionとレスポンシブ表示の優先順位競合

- ミスの内容: 共通 `.action` の `display: inline-flex` が Tailwind の `sm:hidden` より後に適用され、PCでもモバイルメニューボタンが表示された。
- 違反した原則: PoLA、レスポンシブ設計、未確認完了禁止
- 根本原因: 共通コンポーネントの表示プロパティとレスポンシブユーティリティのCSS生成順を、実画面で確認する前提が不足していた。
- 再発防止ルール: 共通クラスが `display` を持つ要素の表示切替は専用クラスで定義し、PC/スマートフォン双方の画像と実DOM寸法で確認する。

### 2026-07-16: コメント送信と管理画面状態の競合

- ミスの内容: コメントの連続送信で同一内容を重複保存でき、管理画面では生成後の入力変更で古い生成コードと新しいプレビューが同時表示され得た。
- 違反した原則: CQS、PoLA、状態管理の安定性
- 根本原因: 操作単位のロックと、入力変更時に派生結果を無効化する状態遷移が明示されていなかった。
- 再発防止ルール: 副作用Commandは再入防止を持たせ、入力から導出した結果は入力変更時に必ず無効化する。高速な連続操作を自動テストへ追加する。

### 2026-07-16: Vitest 4 のテスト発見不全

- ミスの内容: vitest@4.0.18 で `describe`/`it`/`expect` を正しくインポートしているにもかかわらず「No test suite found」エラーが発生し、全テストが0件扱いになった。
- 違反した原則: 動作確認なしのメジャーアップグレード（未確認完了禁止）、安定性優先
- 根本原因: vitest 4.0.x に重大なリグレッションがあり、Windows + ESM 環境でテスト関数の登録が機能しなかった。
- 再発防止ルール: メジャーバージョンのテストランナーを導入する前に `npm test` で smoke test を実行し、テストが1件以上発見されることを確認してから採用する。実績のある安定版（vitest 3.x）を優先する。

### 2026-07-16: コメント入力値の文字数検証がUI層にのみ存在

- ミスの内容: コメントの `maxLength` 制限が `CommentSection.tsx` のインライン属性にのみハードコードされ、ドメイン層に検証ルールが存在しなかった。DOM改ざんで制限を突破可能だった。
- 違反した原則: DRY（文字数制限の知識が1箇所にない）、セキュリティ（UI側のみの検証）、Information Expert
- 根本原因: UIの `maxLength` 属性を唯一の検証として使い、ドメイン層での再検証を忘れていた。
- 再発防止ルール: 入力値検証ルール（文字数制限・空値チェック等）はドメイン層に定義し、UI とロジック双方が同じ定数を参照する。

### 2026-07-16: PostCSS 設定の過剰プラグイン

- ミスの内容: Tailwind CSS v4 (`@tailwindcss/postcss`) と `autoprefixer` を併用していた。Tailwind v4 は Lightning CSS 経由でベンダープレフィックスを自動付与するため、`autoprefixer` は冗長だった。

- 再発防止ルール: フレームワークのメジャーアップグレード後は、旧版専用のプラグイン・設定が不要になっていないか見直す。

### 2026-10-22: 保存データの読み込み失敗後の上書き防止

- ミスの内容: 既存の草案処理はJSON読み込み失敗後もreadyとなり、空の草案を自動保存できた。コメントも読み込み失敗後の新規保存が可能だった。
- 違反した原則: データ保護、Fail Fast。
